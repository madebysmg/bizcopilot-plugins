# 기업 브리핑

BizCopilot 도구 `find_company`, `get_company`로 한 기업의 브리핑을 만든다.

## 순서

1. **기업 확정.** `find_company`에 이름 또는 사업자번호를 넣는다.
   - 후보를 `이름 · 사업자번호 · 대표자 · 지역` 한 줄씩 보여 주고, 사용자가 고를 때까지 상세 조회를 하지 않는다.
   - 사용자가 사업자번호를 줬고 후보가 하나뿐이면 바로 진행한다.
   - `saved: true`는 이미 저장된 기업, `false`는 기업정보 DB에만 있는 기업이다.
2. **한 번에 조회.** 확정한 `company_id`로 `get_company`를 **한 번만** 부른다. 기본 `sections`는 `overview`, `financials`, `ratios`, `officers`, `shareholders`. 요청이 좁으면 줄이고, 필요하면 `offices`(영업소), `related`(관계사), `trade_partners`(거래처), `history`(연혁), `news`, `notes`를 더한다. 같은 기업을 섹션마다 따로 부르지 않는다.
3. **저장되지 않은 기업**(`company_id`가 `warehouse:`로 시작): `overview`만 나온다. 재무·임원은 "웹앱에서 기업을 저장하면 볼 수 있다"고 안내하고 추정으로 채우지 않는다.
4. **일부 섹션 실패:** 응답의 `unavailable`에 이유가 있다. 나온 부분만 쓰고, 빠진 항목은 그대로 알린다.

## 답변 형식

- 맨 위 두세 줄 요약: 무엇을 하는 회사인지, 규모, 눈에 띄는 점.
- 재무는 최근 3개 연도 표: 매출액·영업이익·당기순이익·부채비율. **연도와 단위(원·천원·억원)를 표 제목에 쓴다.**
- 임원과 주주는 표나 목록으로, 지분율은 있는 그대로.
- 끝에 데이터 기준일과 "정보 없음" 항목.

## 규칙

- 값이 없으면 "정보 없음"이라고 쓴다. 비슷한 기업이나 일반 상식으로 채우지 않는다.
- 사업자번호는 가리지 않고 `123-45-67890` 형식으로 쓴다.
- 출처는 "기업정보 DB" 또는 "전자공시(DART)"라고만 쓴다. 데이터 공급사 이름은 쓰지 않는다.
- 금액 단위는 필드 이름과 응답을 보고 확인한다. 확실하지 않으면 단정하지 말고 그렇게 말한다.
- 이 스킬은 조회만 한다. 메모 저장은 `company-notes` 스킬을 따른다.
